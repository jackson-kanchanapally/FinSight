# Phase 8.1 zero-touch thesis validation

Phase 8's proposal, pillar, expectation, and evaluation records remain the source of truth. The current company thesis read uses a saved successful quarterly analysis to create a first thesis when no pillars exist for that company and scope. It groups existing validated proposals by topic, retains their original components and source IDs, then evaluates linked requirements from the saved Phase 7.4 evidence. A new or cached quarterly analysis also triggers this idempotent refresh. The automatic evaluation uses deterministic outcomes and makes no additional Qwen call. The existing explicit evaluation action remains available under **Edit thesis**.

For ESDS's existing Q1 FY2027 consolidated analysis, the automatic path saved five pillars: AI / GPU Growth, Execution, Profitability & Capital Returns, Demand Conversion, and Valuation. All five currently display **Unproven** because the linked future tests have not established delivery or comparable valuation growth. The view reports verified Q1 PAT of ₹29.28 crore as a supported positive, while calling out the unclear total versus additional capital spending. The next big test is Q3 FY27: whether the AI factory in Sydney began generating revenue. This is linked to the stored K1 management checkpoint and is pending; it is not presented as reported revenue. The saved base valuation scenario requires 86.37% annual EPS growth over three years; comparable verified growth is unavailable. Reading the current thesis again leaves the same five pillars and one evaluation run.

Historical `as_of_date` reads do not create or backdate a thesis. Manual edits retain the old revision history and source components. Grouping does not merge unknown, unrelated topics merely to reach a target card count. If research lacks sufficient validated evidence or at least two meaningful groups, no automatic thesis is created. Detailed status, provenance, expectations, diagnostics, and history remain in the API and expandable UI. The main view maps `NOT_YET_TESTABLE` and `INSUFFICIENT_EVIDENCE` to **Unproven**, with the reason or next test still shown.

Validation: backend suite **310 passed, 10 skipped**; focused local ESDS corpus **8 passed** with rollback; frontend production build passed; isolated browser check passed for the empty state, optional editing, cards, summary sections, historical view, and mobile layout. The ESDS activation was retained in the local database so it is visible when that company and scope are opened. No migration was added for 8.1; it uses Phase 8 migration `0018_living_thesis`.

Limits: the initial thesis requires existing verified research. A pending management checkpoint is a test, not proof of delivery. The automatic path deliberately does not ask Qwen for a new narrative, so card interpretation stays concise and sometimes generic until a verified outcome arrives. It does not infer an attractive or demanding valuation verdict from the 86.37% scenario requirement alone.
